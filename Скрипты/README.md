# Скрипты Andrey Local

Три основные категории: **Личные**, **Пение**, **Работа**. **Система ярлыков** находится внутри **Личные**, а **Система GitHub** остаётся отдельной служебной папкой.

Принципы:
- **Один самостоятельный инструмент — одна подпапка**, но его BAT, PS1/AHK/PY, ярлык, конфигурация и README должны оставаться вместе. Не создавать отдельные папки для BAT и PS1 одного инструмента.
- Если в тематической папке несколько независимых инструментов, выделять их в подпапки только с одновременной проверкой путей, ярлыков, задач Планировщика и зависимостей.
- Одна задача = одна папка со скриптом, связанными ресурсами и README.md; простые файлы не дробим на искусственные категории.
- Запускаемые BAT называем по действию на русском, например `Запустить резервное копирование настроек.bat`; внутренние PS1/PY/PYW/AHK могут иметь английские имена.
- У PS1 и консольного PY должен быть BAT-запускатель (за исключением вспомогательных вызываемых модулей).
- Локальные ярлыки `- ярлык.lnk` создаются **рядом с BAT, AHK и PYW**, имеют иконку из общего каталога и не перезаписывают пользовательские изменения.
- Папка `Ярлыки/` больше не заполняется генератором — это личная подборка.
- Файлы проекта сохраняют существующие пути, пока перенос не проверен на регрессии; не переставляй исполняемые файлы отдельно от соседних зависимостей.
- У каждого самостоятельного инструмента должен быть README **простым языком по фактическому коду**: что именно делает (желательно пример «было → стало»), какой BAT/ярлык/AHK запускать, что делают соседние файлы, какие входные данные нужны, какие файлы меняются или создаются, как проверить результат и какие есть риски. При изменении логики обновлять README одновременно с кодом.
- Входящие исходники для проверки — `inbox/scripts`. После подтверждённого использования переносить в `inbox/Done`, не удалять автоматически.

Смотри README внутри каждой тематической папки и `Личные/Система ярлыков/README.md`.
