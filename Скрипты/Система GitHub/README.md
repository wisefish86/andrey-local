# Система GitHub — синхронизация andrey-local

Здесь лежит основная логика обмена файлами между компьютером и публичным GitHub-репозиторием.

| Файл | Назначение |
|---|---|
| `Синхронизация.ps1` | Ручная синхронизация и обновление локальных ярлыков |
| `Автосинхронизация.ps1` | Фоновая синхронизация по заданию Windows |
| `Установить автосинхронизацию.bat` | **Установка по двойному щелчку** |
| `Установить автосинхронизацию.ps1` | Настройка задания планировщика |

**Точки входа оставлены в корне репозитория:** `Синхронизация.bat`, `Синхронизация.ps1`, `Автосинхронизация.ps1`, `Установить автосинхронизацию.ps1` и `Тихий запуск синхронизации.vbs`. Корневые PS1 вызывают рабочие PS1 в этой папке. Это сохраняет уже зарегистрированное задание планировщика и существующие команды.

Важно: рабочие скрипты вычисляют корень репозитория на два уровня выше своей папки; логи и Git-команды должны использовать именно корень.

**Безопасность:** репозиторий публичный, не сохраняй здесь пароли, токены, приватные документы. Автосинхронизация может публиковать любые не исключённые из Git изменения. При конфликтах проверь состояние Git вручную.

При изменении этих файлов проверь ручную синхронизацию, фоновое задание, журнал `.auto-sync.log`, генератор ярлыков и относительные пути. Фактическая проверка работы Windows выполняется на компьютере.

## Установка

Запусти двойным щелчком `Установить автосинхронизацию.bat` в этой папке. BAT запускает установочный PS1 и показывает результат. Он **создаёт или обновляет** задание `AndreyLocal Inbox Auto Sync` в Планировщике Windows; задание выполняется в фоне примерно каждые 2 минуты. Если Git в локальном репозитории по-прежнему выдаёт `bad object`, сначала исправь его или клонируй репозиторий заново — установка задания сама ошибку Git не устраняет.
