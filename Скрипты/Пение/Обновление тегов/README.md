# Обновление тегов MP3

Один универсальный импортёр CSV → ID3 через Mutagen.

## Что запускать

В корне только два пользовательских запуска:

- `Проверить импорт тегов.bat` — dry-run, MP3 не меняются.
- `Применить импорт тегов.bat` — запись после полного preflight.

Можно перетащить CSV на BAT. Если запустить BAT двойным кликом, откроется выбор CSV.

## Структура

```
Обновление тегов/
├─ Проверить импорт тегов.bat
├─ Применить импорт тегов.bat
├─ README.md
├─ config/
│  └─ tag_mapping.json
├─ src/
│  ├─ import_tags.py
│  └─ run_import.bat
└─ templates/
   └─ TagScanner - экспорт тегов для нормализации.txt
```

Старые отдельные `update_tags.py`, `import_tracklist.py`, внутренние BAT, старый `update_tags.csv`, ярлыки и `Desktop.ini` удалены из рабочего контура. При необходимости старые версии остаются в истории Git.

## Как импортёр понимает, куда писать

Mutagen работает с ID3-фреймами: `TPE1`, `TIT2`, `TIT1`, `TCON`, `WOAS` и т. д.

Человеческие названия колонок CSV связаны с ID3 в `config/tag_mapping.json`.

Например:

```json
"Исполнитель": {"kind": "text", "frame": "TPE1", "empty": "clear"},
"Название": {"kind": "text", "frame": "TIT2", "empty": "clear"},
"Теги": {"kind": "text", "frame": "TIT1", "multi": true, "empty": "clear"},
"Ситуация": {"kind": "txxx", "frame": "TXXX:OCCASION", "empty": "clear"},
"WWWSOURCE": {"kind": "url", "frame": "WOAS", "empty": "clear"}
```

Поэтому Python не угадывает смысл колонки и не привязан только к текущему TrackList.

### Универсальный режим

Если в CSV колонка уже называется настоящим ID3-фреймом, дополнительная настройка не нужна. Поддерживаются, например:

- `TPE1`, `TIT2`, `TALB`, `TCON`, `TIT1` и другие стандартные текстовые T-фреймы;
- `TXXX:OCCASION` и другие пользовательские TXXX;
- `WOAS` и другие стандартные URL W-фреймы;
- `WXXX` или `WXXX:Описание`;
- `COMM`;
- `POPM`.

Если появляется новое человеческое имя колонки, достаточно добавить одну запись в JSON — Python менять не нужно.

Неизвестная колонка не игнорируется молча: preflight остановится и напишет, что нужно добавить mapping.

## Текущий TrackList

Для текущего экспорта используются:

| CSV | ID3 |
|---|---|
| Исполнитель | TPE1 |
| Название | TIT2 |
| НазваниеЧистое | MVNM |
| Альбом | TALB |
| АльбомАртист | TPE2 |
| Год | TDRC |
| Жанр | TCON |
| Настроение | TMOO |
| Теги | TIT1, multi-value |
| Ситуация | TXXX:OCCASION |
| Комментарий | COMM |
| Композитор | TCOM |
| АвторСлов | TEXT |
| Издатель | TPUB |
| Рейтинг | POPM |
| WWW | WXXX |
| WWWSOURCE | WOAS |

`ПолныйПуть` — адрес конкретного MP3. `Индекс` игнорируется.

Важно: названия `Жанр`, `Настроение`, `Ситуация` — это исторические названия колонок TagScanner. Их фактический смысл в системе Андрея определяется содержимым тегов и GUI будущей программы.

## Безопасность

Перед любым apply импортёр сначала проверяет **весь CSV**:
- есть ли колонка пути;
- нет ли неизвестных/дублирующихся колонок;
- существует ли каждый MP3;
- нет ли одного пути дважды;
- корректны ли валидируемые значения.

Если preflight не прошёл, запись не начинается.

Перед записью рядом с исходным CSV создаётся:
`data/<имя CSV>_backup_before_import_YYYY-MM-DD_HH-MM-SS.csv`

После каждого сохранения MP3 открывается заново и изменённые поля сверяются. При ошибке скрипт пытается откатить конкретный файл и прекращает дальнейшую запись.

Пустая ячейка по умолчанию очищает управляемый тег. Для рейтинга в текущем JSON стоит `empty: preserve`, поэтому пустой рейтинг не удаляет POPM.

## TagScanner

Шаблон экспорта лежит в:
`templates/TagScanner - экспорт тегов для нормализации.txt`

Lyrics, BPM, Track и ReplayGain в этот CSV намеренно не входят.

## Проверка после изменений

1. Перетащить CSV на `Проверить импорт тегов.bat`.
2. Убедиться, что `Errors: 0`.
3. Перетащить тот же CSV на `Применить импорт тегов.bat`.
4. Проверить несколько файлов в TagScanner/MusicBee.

Python и Mutagen нужны локально. Если Mutagen отсутствует, launcher пытается установить его автоматически.
