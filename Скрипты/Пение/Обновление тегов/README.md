# Обновление музыкальных тегов

Основной универсальный Python-файл: `update_tags.py`. Список изменений для старого режима: `update_tags.csv`.

**Запускай через BAT с понятным названием:**
- `Проверить обновление тегов.bat` — старый универсальный dry-run; вызывает `check_only.bat`.
- `Применить обновление тегов.bat` — старое универсальное применение; вызывает `apply_all.bat`.

Существующие `check_only.bat`, `apply_all.bat` и `install_mutagen.bat` оставлены для совместимости.

## Импорт полного TrackList CSV обратно в MP3

Для CSV формата `TrackList_ИТОГОВЫЙ_ДЛЯ_ИМПОРТА.csv` используется отдельный `import_tracklist.py`.

Пользовательские BAT:
- `Проверить импорт тегов из CSV.bat` — только показать, что будет изменено.
- `Применить импорт тегов из CSV.bat` — записать значения в MP3.

CSV можно:
1. положить рядом со скриптами под именем `TrackList_ИТОГОВЫЙ_ДЛЯ_ИМПОРТА.csv`;
2. либо перетащить CSV мышью на нужный BAT.

Импорт идёт **по точному значению колонки `ПолныйПуть`**, а не по порядку строк в TagScanner.

### Какие колонки записываются

- `Исполнитель` → TPE1
- `Название` → TIT2
- `НазваниеЧистое` → MVNM
- `Альбом` → TALB
- `АльбомАртист` → TPE2
- `Год` → TDRC
- `Жанр` → TCON
- `Настроение` → TMOO
- `Теги` → TIT1, несколько значений через `;`
- `Ситуация` → TXXX:OCCASION
- `Комментарий` → COMM
- `Композитор` → TCOM
- `АвторСлов` → TEXT
- `Издатель` → TPUB
- `Рейтинг` → POPM
- `WWW` → WXXX
- `WWWSOURCE` → WOAS

`Индекс` служебный и не записывается. `ПолныйПуть` используется только для поиска конкретного MP3.

Пустая ячейка очищает соответствующее управляемое поле. Исключение: пустой `Рейтинг` не трогает существующий POPM, чтобы случайно не потерять рейтинг/счётчик проигрываний.

### Безопасность

Перед любым `--apply` скрипт сначала проверяет **весь CSV**:
- совпадает ли структура и порядок колонок;
- заполнены ли пути;
- существуют ли все MP3;
- нет ли одинакового пути дважды;
- все ли цели имеют расширение MP3;
- корректны ли формат года и рейтинга.

Если preflight нашёл проблему, **ни один MP3 не изменяется**.

Перед записью создаётся резервный CSV текущих управляемых тегов:
`data/TrackList_backup_before_import_YYYY-MM-DD_HH-MM-SS.csv`
рядом с импортируемым CSV.

После каждого изменённого MP3 файл заново открывается через Mutagen и каждое изменённое поле сверяется. Если проверка конкретного файла не прошла, скрипт пытается откатить его управляемые теги и останавливает дальнейшее применение.

Массовой транзакции файловой системы нет: если ошибка возникнет уже после нескольких успешно обработанных файлов, предыдущие файлы останутся изменёнными. Для возврата используется автоматически созданный backup CSV.

### Рекомендуемый порядок

1. Сначала запусти `Проверить импорт тегов из CSV.bat`.
2. Убедись, что в конце `Errors: 0` и все 559 путей найдены.
3. Затем запусти `Применить импорт тегов из CSV.bat`.
4. После завершения проверь несколько песен в TagScanner/MusicBee.

## TagScanner: экспорт для аудита и массовой нормализации

Шаблон `TagScanner - экспорт тегов для нормализации.txt` выгружает в `TrackList.csv` смысловые поля: исполнитель, название, чистое название, альбом, альбом-артист, год, жанр, настроение, группировка/теги, ситуация, комментарий, композитор, автор слов, издатель, рейтинг, WWW, WWW Source и полный путь.

Намеренно не выгружаются Lyrics, BPM, Track и ReplayGain: они не нужны для текущей миграции системы тегов и не должны случайно перезаписываться.

## Требования

Нужны Python и пакет Mutagen. Если Mutagen ещё не установлен, запусти `install_mutagen.bat`.

**Ярлыки:** генератор `Скрипты/Система ярлыков/Обновить ярлыки.bat` создаёт локальные `.lnk` рядом с BAT. Отдельные ярлыки для Python-файлов не нужны.

**Осторожно:** применение изменяет метаданные музыкальных файлов. Сначала всегда используй режим проверки.
