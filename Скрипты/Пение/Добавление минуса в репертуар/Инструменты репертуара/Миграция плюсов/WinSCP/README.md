# Миграция плюсов через WinSCP

Резервный и рекомендуемый способ для массовой разовой миграции, когда FTP из Python нестабилен.

## 1. Подготовить файлы

Запустить:

\`1. Подготовить плюсы для WinSCP.bat\`

Скрипт:

- сканирует тот же репертуар и использует ту же логику выбора плюса, slug/transliteration и WOAS, что основной мигратор;
- сохраняет уже существующие рабочие WOAS и не включает такие минусовки в работу;
- проверяет канонический публичный URL: если плюс уже доступен на сайте, повторно копировать его для WinSCP не нужно;
- остальные плюсы копирует в одну папку \`data/migration_plus_links/winscp_upload\`;
- копии сразу получают итоговые серверные имена;
- создаёт \`winscp_manifest.json\` с соответствием плюс → URL → ожидающие минусовки;
- открывает папку с файлами в Проводнике.

Оригинальные MP3 не переименовываются и не перемещаются.

## 2. Загрузить через WinSCP

Загрузить **содержимое** \`winscp_upload\` в FTP-папку, указанную в файле:

\`data/migration_plus_links/WinSCP - КУДА ЗАГРУЖАТЬ.txt\`

Не создавать на сервере дополнительную папку \`winscp_upload\`.

## 3. Прописать WOAS

После окончания загрузки запустить:

\`2. Прописать WOAS после WinSCP.bat\`

Скрипт не использует FTP. Для каждого элемента манифеста он:

1. проверяет публичный HTTPS URL;
2. если URL работает — перечитывает текущий WOAS каждой ожидающей минусовки;
3. существующий рабочий WOAS сохраняет без изменений;
4. отсутствующий или нерабочий WOAS заменяет каноническим URL;
5. после записи использует существующую проверенную функцию ID3-записи с повторным чтением тега.

Если часть файлов не загрузилась или ещё не доступна по HTTPS, WOAS для них не меняется. Создаётся:

\`data/migration_plus_links/WinSCP - НЕ ЗАГРУЖЕНО.txt\`

После догрузки этих файлов через WinSCP второй BAT можно безопасно запустить повторно.

## Отчёты

История подготовки и применения:

\`data/migration_plus_links/winscp_reports\`

Текущий манифест:

\`data/migration_plus_links/winscp_manifest.json\`


## Канонизация WOAS

Для этой миграции единственный целевой WOAS — публичный URL из `plus_upload.public_base_url`.

Рабочая сторонняя ссылка не считается причиной пропускать файл. Если в MP3 уже стоит Яндекс.Диск, другой домен или другой путь, после успешной HTTPS-проверки канонического файла ссылка заменяется.

Итоговый отчёт отдельно показывает:
- сколько WOAS реально записано/заменено;
- сколько старых/сторонних ссылок заменено;
- сколько пустых WOAS заполнено;
- сколько уже были каноническими и не потребовали записи.
