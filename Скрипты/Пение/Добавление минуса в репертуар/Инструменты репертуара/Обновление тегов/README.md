# Обновление тегов MP3

Один универсальный импортёр CSV → ID3 через Mutagen.

## Как пользоваться

Для обычной работы нужен **один файл**:

**`Импорт тегов из CSV.bat`**

Есть два способа:

1. Перетащи CSV мышью на `Импорт тегов из CSV.bat`.
2. Либо запусти BAT двойным кликом и выбери CSV в окне.

Дальше всё идёт одним сценарием:

1. Скрипт сначала делает **полную проверку без изменения MP3**.
2. Если проверка не прошла — он останавливается, ничего не записывая.
3. Если всё нормально, появляется выбор:
   - `1` — записать изменения;
   - `2` — отменить.
4. Перед записью создаётся backup текущих управляемых тегов.
5. После каждого изменённого MP3 теги перечитываются и сверяются.

То есть отдельные BAT «проверить» и «применить» больше не нужны.

## Как импортёр понимает, куда писать

Mutagen работает с ID3-фреймами: `TPE1`, `TIT2`, `TIT1`, `TCON`, `WOAS` и т. д.

Человеческие названия колонок CSV связаны с ID3 в `config/tag_mapping.json`.

Например:

```json
"Исполнитель": {"kind": "text", "frame": "TPE1", "empty": "clear"},
"Название": {"kind": "text", "frame": "TIT2", "empty": "clear"},
"Теги": {"kind": "text", "frame": "TIT1", "multi": true, "empty": "clear"},
"Ситуация": {"kind": "txxx", "frame": "TXXX:OCCASION", "empty": "clear"},
"WWWSOURCE": {"kind": "url", "frame": "WOAS", "empty": "clear"}
```

Поэтому Python ничего не угадывает: mapping явно задаёт, какая колонка куда записывается.

### Универсальный режим

Если колонка CSV уже называется настоящим ID3-фреймом, отдельный mapping не нужен. Поддерживаются, например:

- `TPE1`, `TIT2`, `TALB`, `TCON`, `TIT1`;
- `TXXX:OCCASION`;
- `WOAS` и другие стандартные URL W-фреймы;
- `WXXX` или `WXXX:Описание`;
- `COMM`;
- `POPM`.

Если появляется новое человеческое имя колонки, достаточно добавить его в JSON. Python менять не нужно.

Неизвестная колонка не игнорируется молча: preflight остановит импорт и покажет ошибку.

## Безопасность

Перед записью проверяется весь CSV:
- есть ли колонка пути;
- нет ли неизвестных или дублирующихся колонок;
- существует ли каждый MP3;
- нет ли одного пути дважды;
- корректны ли валидируемые значения.

Если preflight не прошёл, запись не начинается.

Перед apply резервный CSV сохраняется **внутри этого инструмента**:
`Обновление тегов/data/backups/<имя CSV>_backup_before_import_YYYY-MM-DD_HH-MM-SS.csv`.
Исходный выбранный CSV остаётся на своём месте. Старые копии возле CSV не удаляются.

После каждого сохранения MP3 открывается заново и изменённые поля сверяются. При ошибке скрипт пытается откатить конкретный файл и прекращает дальнейшую запись.

Пустая ячейка по умолчанию очищает управляемый тег. Для рейтинга в текущем JSON стоит `empty: preserve`, поэтому пустой рейтинг не удаляет POPM.
