# Аудит ID3 и пакетный обмен JSON

Два отдельных режима: **компактный редактируемый JSON** для обмена с GPT и безопасного пакетного импорта, а также прежний **подробный аудит** для исследования редко используемых ID3-фреймов. Ни один экспорт не изменяет исходные MP3.

## Для GPT — отдельный обмен

- `Экспортировать теги для GPT.bat` → `data/exports/repertoire_for_gpt_*.json`.
- `Импортировать теги GPT — ПРОВЕРКА.bat` → план без записи.
- `Импортировать теги GPT — ПРИМЕНИТЬ.bat` → запись изменённых полей с резервными MP3.
- Менять в JSON только значения `tracks[].tags`, а не ключи, пути, ID или контрольные хеши.

В GPT-обмене **только редактируемые поля программы**: `TPE1`, `MVNM`, `TIT2`, `TDRC`, `WOAS`, `TPE2`, `TXXX:OCCASION`, `TMOO`, `TCON`, `TIT1`. Список определяется полями основного `config.json` и `Аудит ID3/config.json → gpt_simple_fields`.

**Не включаются:** BPM/`TBPM`, ReplayGain, рейтинг/`POPM`, лирика, обложки, технические фреймы, фиксированный альбом `TALB`. В GPT-импорте эти значения также запрещены. Импорт принимает только формат `andrey_repertoire_gpt` версии 2.

**Полный аудит отдельно:** `Экспортировать все ID3 в JSON.bat` → `export_all_id3.py`; его JSON в GPT-импорт не подходит.

### Безопасность импорта

- Перед записью проверяются существование файлов, пути, идентификаторы, размер и время изменения с момента экспорта, хеши каждого тега, допустимость типов и общее число затронутых MP3. **Любой конфликт останавливает применение без массовой записи**.
- Режим **ПРОВЕРКА** только формирует план. Режим **ПРИМЕНИТЬ** сначала сохраняет **полные резервные MP3** всех затрагиваемых песен в `Аудит ID3/data/backups/<дата-время>/`; только затем изменяет ID3.
- После записи каждый изменённый тег перечитывается и проверяется. При ошибке запускается откат записанных MP3 из полных резервных копий. Копии не удаляются автоматически.
- Все отчёты лежат в `Аудит ID3/data/reports/`, вся служебная папка `data/` исключена из Git. Лимит `max_changed_tracks` ограничивает массовую запись.
- **После пакетного исправления статусов или тематических тегов** отдельно запусти обновление Syncthing и перескан для Singer Andrey: импорт JSON сам их не запускает.

Настраиваемые параметры в локальном `Аудит ID3/config.json`: `excluded_folders` (по умолчанию Files, Additi0ns и staging), `max_text_chars`, `gpt_simple_fields` (простые редактируемые поля основного окна), `max_changed_tracks`. Корень репертуара и символ `֎` берутся из **единого главного** `Добавление минуса в репертуар/config.json`, чтобы не дублировать пути.

## Подробный аудит (старый формат, только для анализа)

Прежний скрипт **`export_all_id3.py`** сохранён. Для подробного экспорта открой консоль в папке «Аудит ID3» и запусти `py -3 export_all_id3.py`. Такой JSON содержит дополнительные атрибуты и технические параметры аудио, но **не подходит для обратного импорта**. Для сверки с публичным экспортом можно добавить `--use-site-excludes`.

### Что попадает в подробный JSON

Для каждого файла сохраняются:

- абсолютный и относительный путь;
- имя, размер и время изменения файла;
- технические параметры MP3, которые отдаёт Mutagen;
- удобная сводка текущих рабочих тегов: TPE1, MVNM, TIT2, TALB, TPE2, TDRC, TCON, TMOO, TIT1, TXXX:OCCASION, TBPM, WOAS, рейтинг, ReplayGain;
- все распознанные ID3-фреймы, **кроме USLT, SYLT, APIC, GEOB и PRIV**;
- атрибуты каждого фрейма;
- небольшие бинарные атрибуты прочих разрешённых фреймов в base64; тяжёлые вложения APIC/PRIV и подобные в JSON не включаются;
- ошибки чтения по конкретным файлам;
- агрегированная статистика типов ID3-фреймов.

Результат создаётся в:

data/id3_full_export_YYYY-MM-DD_HH-MM-SS.json

Локальная папка `Аудит ID3/data/` исключена из Git. Ранее созданные отчёты в общей `../../data/id3_audit/` автоматически не удаляются.

## Важно о подробном аудите

Подробный JSON — исследовательский снимок, а не редактируемый формат. Не загружай его в новый импортёр; для этого заново выгрузи **компактный** JSON через BAT.

Оба режима работы с ID3 используют общие функции чтения/записи тегов из `_common/id3_io.py`. Универсальный CSV-импорт тегов в `Обновление тегов/src/import_tags.py` остаётся отдельным инструментом, его существующие операции не менялись.

## Очистка устаревших тегов (без дополнительного резервного копирования)

- `Проверить очистку.bat` — только просмотр; MP3 не меняются.
- `Применить очистку.bat` — удаляет `PRIV:XMP`, `WOAF`, `WOAR`, `WXXX`, `WCOP`, `TCOP`, `TOPE`, `TSSE`, `GEOB`, `TIT3`, `TKEY`, `TCMP`, `TDEN`, `TENC` из MP3 с маркером `֎` рекурсивно в основной фонотеке.
- **Сохраняет** `WOAS` (ссылки Singer Andrey), `APIC` (обложки), `USLT`/`SYLT` (лирику), `POPM`, ReplayGain и все рабочие теги. `PRIV` других владельцев не трогает.
- Отчёт создаётся в `Аудит ID3/data/cleanup_preview_*.json` или `Аудит ID3/data/cleanup_apply_*.json` (в папке текущего инструмента).
- Дополнительную копию скрипт не создаёт: перед запуском применения убедиться, что собственный ZIP-архив фонотеки сохранён и доступен.
- При ошибке обработки применение останавливается на проблемном файле. Отдельной функции отката нет.
