# Распределение минусов для телефона

## Копирование по ID3-статусам (Python)

**Источник:** задаётся в соседнем `config.json` → `source_root` (по умолчанию основная фонотека).

**Назначение:** соседний `config.json` → `target_root` (по умолчанию папка Syncthing на телефон).

**Запуск:**

- `Разложить для телефона — ПРОВЕРКА.bat` — предварительный просмотр, не создаёт и не удаляет музыкальные файлы;
- `Разложить для телефона — ОБНОВИТЬ.bat` — копирует/обновляет данные и убирает только устаревшие копии, ранее созданные **этим Python-инструментом**;
- обе операции доступны кнопками в разделе «Инструменты репертуара» программы;
- оба BAT запускают общий `Разложить для телефона.py`; ярлыки называются так же, как соответствующие BAT, с добавлением ` - ярлык`. Состояние и отчёты — исключительно в `Распределение минусов/data/`.

**Статусы** определяются **только** реальными ID3 `TXXX:OCCASION` (не по названиям исходных папок). Таблица ниже — начальные значения редактируемого `config.json → status_directories`:

| Значение | Папка назначения |
| --- | --- |
| `г-1-База` | `01 База` |
| `г-2-Рабочие` | `02 Рабочие` |
| `г-3-Тестирую` | `03 Тестирую` |
| `г-4-Повторить` | `04 Повторить` |
| `г-5-Выучить` | `05 Выучить` |
| `г-6-Запас`, `г-7-Версии` и пустой/неизвестный статус | не создают отдельную папку песни |

В каждую папку статуса копируются **папки песен**, внутри — только файлы, лежащие непосредственно в исходной папке (без вложенных подпапок). Это сохраняет минусовки, плюсовки и файлы текстов. MP3 с тегами «Запас» и «Версии» в них не копируются, даже если в папке есть разрешённая версия. При нескольких разрешённых статусах внутри одной папки песня может появиться в нескольких категориях, но каждый конкретный MP3 попадёт только в свой статус. Дополнительные файлы песни верхнего уровня могут повторяться в этих категориях.

**По умолчанию исключаются только `Additi0ns` (цифра 0) и `Files`.** Список настраивается в `config.json → excluded_folders`. Исключения сканера сайта сюда не подмешиваются.

### Единое предложение обновить телефон и сайт после сохранения минуса

После **успешного сохранения и проверки MP3** основная программа «Добавление минуса в репертуар» показывает одно предложение запустить **оба** инструмента, если:

- новый минус перенесён из папки добавления в основной репертуар и имеет рабочий статус для телефона;
- статус `TXXX:OCCASION` изменился так, что песня попадает в новую категорию Syncthing или больше не копируется на телефон.

Изменение других полей и сохранение без изменения категории не запускают предложение. При переходах между двумя исключёнными категориями (например, «Запас» → «Версии») предложения нет.

**В диалоге только два варианта:**
- **«Запустить оба»** — одновременно открыть штатные BAT: `tools.phone_sync_apply` (обновить папки Syncthing) и `tools.site_rescan` (пересканировать Singer Andrey, создать JSON и загрузить публичный каталог через WinSCP).
- **«Позже»** — ничего не запускать. Этот вариант выбран по умолчанию.

Дополнительного вопроса или промежуточной проверки нет. Два BAT выполняются в **отдельных консольных окнах**, исходные MP3 не изменяются. После изменения статуса старые управляемые копии удаляются по защитным правилам скрипта; удаления через Syncthing синхронизируются с телефоном. Открытие обоих процессов не доказывает завершения операций: статусы и ошибки смотреть в окнах BAT.

Параметры триггера: `config.json → post_save_prompt` (`enabled`, `on_new_song`, `on_status_change`, `status_field_id`). Пути BAT не дублируются: они задаются в **главном** `Добавление минуса в репертуар/config.json → tools.phone_sync_apply` и `tools.site_rescan`.

### Что редактировать в config.json

В одной папке с `Разложить для телефона.py` лежит `config.json`. Основные параметры:

| Ключ | Назначение |
| --- | --- |
| `source_root` | Абсолютный путь к исходной папке репертуара |
| `target_root` | Абсолютный путь к папке копий Syncthing |
| `filename_marker` | Маркер основной MP3-минусовки в имени (по умолчанию `֎`) |
| `excluded_folders` | Массив исключаемых подпапок, например `["Additi0ns", "Files"]` |
| `status_directories` | Соответствия значений ID3 `TXXX:OCCASION` и имён папок в Syncthing |
| `excluded_statuses` | Статусы MP3, которые никогда не копируются (сейчас «Запас» и «Версии») |
| `post_save_prompt` | Когда главная программа предлагает обновить папки телефона после сохранения MP3 |

**Менять JSON можно без изменения Python.** Пути Windows в JSON записываются с удвоенными обратными слешами. Названия папок в `status_directories` — ровно один компонент пути, без слешей, двоеточий и специальных имён Windows. Скрипт проверяет типы и конфликты настроек до начала операций. Изменение категории приведёт к переносу управляемых копий при следующем обновлении. Перед изменением `target_root` проверь, что это действительно нужный каталог: старый каталог останется, а в новом будет создан независимый набор копий.

CLI-параметры `--config`, `--source`, `--target` могут временно переопределять настройки; обычные BAT используют `config.json`. При режиме `--apply` необходимо переопределять `--source` и `--target` вместе.

### Защита данных

- Исходники не изменяются и не перемещаются. Старый перенос папок по плейлистам MusicBee удалён из репозитория; если когда-нибудь понадобится, его можно восстановить из истории Git.
- Для защиты существующих файлов новое средство запоминает свои копии в `data/manifests/<ID папки назначения>.json`. Оно **не перезаписывает и не удаляет** чужие или вручную изменённые файлы: в таком случае выдаёт ошибку до начала операций.
- При изменении статуса старые управляемые копии удаляются из прежней категории, только если их не изменяли с предыдущего запуска. **Удаления в Syncthing синхронизируются с телефоном.**
- **Если статус меняется** (например, «Рабочие» → «Тестирую»), сначала создаётся копия в новой категории, затем убираются старые управляемые файлы. После этого удаляется **пустая папка песни** из прежней категории. Пустые корневые папки категорий (`01 База`, `02 Рабочие` и т. д.) сохраняются для навигации. Если в старой папке остались вручную добавленные файлы, сама папка сохраняется и указывается в отчёте.
- Режим **«ПРОВЕРКА»** показывает `folders_to_cleanup_if_empty`. Режим «ОБНОВИТЬ» записывает фактически удалённые `removed_folders` и оставленные непустые `nonempty_folders_kept` в JSON-отчёт.
- Журнал каждого запуска с действиями по файлам сохраняется в `data/reports/sync_YYYYMMDD_HHMMSS.json`. `data/` исключена из GitHub через `.gitignore`.
- При повторном запуске неизменённые файлы не копируются заново. Если один и тот же конечный путь подходит двум исходным файлам, запуск останавливается без изменений (коллизия имени).
- Не удаляй `data/manifests/`: там хранятся реестры всех использованных папок назначения. Старый `data/syncthing_manifest.json` версии 1 автоматически читается для исходного пути Syncthing и остаётся нетронутым; при первом обновлении для этого назначения создаётся новый реестр. При смене `target_root` создаётся **отдельный реестр**; прежняя папка назначения и её файлы не очищаются автоматически.

**Перед первым обновлением** выполни «ПРОВЕРКА», посмотри число папок/файлов и JSON-отчёт, затем «ОБНОВИТЬ». Для работы нужен Python с `mutagen`, который уже используется программой добавления минусов. Реальная синхронизация на компьютере ещё требует проверки.
