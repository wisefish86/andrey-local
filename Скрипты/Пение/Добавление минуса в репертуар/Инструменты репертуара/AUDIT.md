## Инвентаризация

### Сайт Singer Andrey

Пересканировать репертуар для Singer Andrey.py:

- читает paths.library_root;
- берёт только MP3 с ֎;
- использует служебные исключения;
- пишет data/site/repertoire.json;
- MP3 не изменяет;
- использует общий _common/id3_io.py.

Статус: актуальная хорошая база для будущего публичного каталога, но не полный аудит ID3.

legacy-old-site/:

- старая цепочка songs.csv → converter.py → songs.js;
- в README явно помечена как legacy.

Статус: оставить архивом, не развивать.

### Обновление тегов

src/import_tags.py + config/tag_mapping.json + Импорт тегов из CSV.bat.

Сильные стороны:

- общий _common/id3_io.py;
- полный preflight всего входного CSV;
- backup управляемых тегов перед apply;
- повторное чтение после записи;
- rollback конкретного файла при ошибке проверки;
- остановка apply после первой ошибки;
- неизвестные колонки не игнорируются молча.

Статус: главная база для будущего безопасного импорта/очистки.

Ограничение: текущий формат входа — CSV и только явно сопоставленные поля; он не предназначен для анализа всех неизвестных ID3-фреймов.

### Исправление лирики

mp3_lyrics_gui.py:

- специализированный GUI для SYLT ↔ USLT;
- умеет находить конфликты и редактировать лирику;
- пишет теги напрямую через Mutagen;
- сохранение выполняется через tags.save(..., v2_version=3).

Риск: код живёт отдельно от _common/id3_io.py, а перед tags.save нет общего механизма backup/verify/rollback, как в новом импортёре тегов.

Статус: рабочий специализированный инструмент, но потенциальный кандидат на унификацию безопасности позже. Сейчас не смешивать с массовой очисткой тегов.

### Подготовка фонотеки

PowerShell + BAT + внешний TXT правил.

- меняет только имена выбранных файлов;
- есть -WhatIfMode;
- обычный BAT запускает реальное переименование;
- при коллизии целевого имени файл пропускается.

Статус: отдельная операция по именам файлов, к ID3-аудиту не относится.

### Распределение минусов

PowerShell + BAT.

- читает конкретные MusicBee .m3u;
- содержит жёстко заданные локальные пути;
- принудительно завершает MusicBee через Stop-Process -Force;
- перемещает целые папки Move-Item -Force.

Статус: самый операционно рискованный инструмент папки. Его нельзя использовать как часть автоматической очистки/каталога. Перед будущим рефакторингом стоит вынести пути/задачи в конфиг и добавить полноценный dry-run.

### Нормализация аудио видео

Один старый drag-and-drop BAT с ffmpeg.

- видеопоток копируется;
- к аудио применяется alimiter;
- создаётся соседний _norm файл.

Статус: изолированный legacy-инструмент, к репертуарным тегам не относится.

## Принятая архитектура каталога

Разделяем три разных слоя:

1. Полный аудит — Аудит ID3: сохраняет вообще все ID3-фреймы, ничего не меняет.
2. Внутренний канонический каталог — следующий этап после просмотра реальных данных; содержит только осмысленные поля для отбора и конструктора программ.
3. Публичный repertoire.json сайта — узкая производная от внутреннего каталога, без текста песни и служебного мусора. Технические версии одной песни позднее объединяются по Artist/TPE1 + MVNM; TIT2 остаётся названием конкретной версии.

Так один источник данных можно использовать и для очистки тегов, и для конструктора программ, и для сайта, не смешивая разные задачи в одном JSON.
