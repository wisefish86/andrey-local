# Конструктор плейлистов — каталог репертуара и редактор

Локальная Windows-программа. Запуск: двойной щелчок по `Конструктор плейлистов.pyw` (Python 3.10+).
Используются PySide6 и mutagen, как в существующем приложении для минусовок.
Если библиотек нет, программа спрашивает разрешение на установку через pip.

## Автоматический каталог минусов

При запуске программа читает `config.json` рядом с `app.py`. Настройки:
- `library.path` — основная папка с минусовками;
- `library.filename_contains` — обязательный маркер в имени MP3 (по умолчанию `֎`);
- `library.recursive` — поиск во вложенных папках;
- `library.exclude_directories` — исключённые папки (включая временные);
- `library.auto_load` — сканировать каталог при запуске.

Из панели «Каталог минусов» можно перетаскивать песни в «Текущий плейлист»
или выделять их и нажимать «→ В плейлист». Кнопка «↻ Обновить»
пересканирует папку, но не изменяет состав текущего плейлиста.
Каталог доступен только для чтения. MP3 не меняются, не копируются и не удаляются.
При недоступной папке ошибка выводится в строке состояния.
Загрузка идёт в отдельном рабочем потоке.

## Быстрая проверка с MusicBee / AIMP

1. Открой оба приложения с одинаковыми правами (не запускай одно из них от администратора).
2. Выдели 2–3 MP3 в MusicBee и перетащи в «Текущий плейлист». Появятся ID3-поля.
3. Перетащи строки из конструктора назад в MusicBee/AIMP. Передаются ссылки на реальные файлы через file-URL и CopyAction.
4. Выдели песни и нажми Delete / «Убрать». Удаляются только строки, файлы остаются.
5. Переставляй строки перетаскиванием или ↑/↓; «Заменить…» вставляет другие файлы вместо выделенных.
6. Перетащи старый M3U8 в таблицу «История прошлого выступления» — увидишь процент общих песен.
7. «Сохранить M3U8» создаёт плейлист с абсолютными путями для MusicBee/AIMP.

Если MusicBee не отдаёт файловые пути при переносе, он может использовать собственный
drag-drop формат. Сделай скриншот текста строки состояния с форматами; альтернативно
перетащи MP3 из Проводника или M3U8, экспортированный из MusicBee. Вывод из
конструктора тоже требует проверки конкретной области окна MusicBee.

## Защита исходной фонотеки

- Код не изменяет ID3, не копирует, не переносит и не удаляет MP3.
- Удаление и замена работают только с записями таблицы; внешнее перетаскивание — CopyAction.
- Источник тегов — общий `_common/id3_io.py`. Программа работает офлайн.
- Записывается только явно выбранный в системном диалоге файл M3U8.
- M3U8 хранит ссылки, а не копии аудио; пути никуда не отправляются.

## Следующий этап (пока не реализовано)

- Пресеты ресторанов, четыре блока и личные резервы каждого блока.
- Ограничения вокальной нагрузки SL1–SL4: SL3 → SL1, сложные песни не подряд.
- Ручное закрепление, автоматическая замена по вайбу и сложности, 3–5 вариантов.
- История конкретного заведения: реально спетые песни, 10–20% повторов.
- Правила рус/иностранных, темпа, энергии, рейтинга, узнаваемости и длительности.
- Экспорт точных служебных разделителей только из уже известного эталонного M3U.

## Проверки

GitHub Actions `Setlist editor checks`: unit-тесты безопасного M3U8/ID3 и
smoke-тест интерфейса Qt без экрана. Реальный Windows DnD в MusicBee/AIMP
проверяется отдельно; до этого его совместимость не считать подтверждённой.

## Быстрая замена и группировка версий

В каталоге показывается одна техническая версия на пару `TPE1 + MVNM`.
Если MVNM отсутствует, версии не объединяются автоматически: нужен ручной разбор,
чтобы не ошибиться с разными песнями. При переносе в текущий плейлист дубли
одной песни исключаются. Кнопка «Заменить ↻» подбирает следующую доступную
композицию с приоритетом той же роли в блоке (TPE2), энергии (TCON) и
сложности (TMOO). Повторные нажатия в одной позиции исключают уже отвергнутые
варианты. «Выбрать файл…» остаётся для ручной замены. Исходные MP3 не меняются.

Следующие UX-этапы: редактируемые блоки с DnD между ними, закрепления песен,
сохранение JSON-проекта выступления и ресторанных пресетов; пока не реализованы.
Для каверов/оригиналов нужен отдельный явно заполняемый идентификатор
музыкального произведения; нельзя склеивать их только по похожему названию.

## Группа произведения V- (каверы и ремиксы)

В существующем ID3 `TIT1` можно назначить один общий тег `V-<код>` всем
версиям **одного музыкального произведения**, даже у разных исполнителей.
Пример: `V-burito-mama` в оригинале, акустической версии, ремиксе и кавере.
Это не тип версии (cover/remix), а устойчивый идентификатор произведения.
Конструктор считывает тег без изменений MP3 и запрещает повтор такого
произведения в каталоге/плейлисте и среди быстрых замен.

Если `V-` отсутствует, продолжает действовать проверка `TPE1 + MVNM`;
если нет и `MVNM`, разные файлы автоматически не склеиваются.
Сейчас поддерживается **чтение** `V-` в конструкторе; отдельный удобный
редактор этого тега в основной программе ещё предстоит добавить.
Все версии произведения должны иметь один код; частичная разметка
не гарантирует обнаружение дублей между размеченным и неразмеченным файлами.

## Фильтры ресторана и восстановление сессии

Фильтры находятся над левым каталогом. Выбери ресторан или нажми **Настроить фильтры…**. Пресет хранит отдельные списки разрешённых языков, сложностей и энергий (переключатели), а также текстовые наборы тегов для включения и исключения. Пустой список переключателей означает, что категория не ограничена. Исключения имеют приоритет; среди включённых тегов достаточно любого совпадения.

В пресете сохраняется целевая доля английских песен (по умолчанию 50%). Рядом с фильтром можно указать количество песен и нажать **Добрать по доле языков**: программа дополняет текущий список из отфильтрованного каталога русскими/английскими композициями, приближаясь к нужной доле. Ручной порядок уже добавленных песен сохраняется, существующие песни не удаляются, повторы общего тега произведения `в-` не добавляются. При недостатке подходящих файлов подбор может завершиться раньше цели. Иностранные с языком `Я-ин` автоматически не распределяются как русские либо английские.

Последний выбранный ресторан и состав текущего плейлиста сохраняются при обычном закрытии редактора в локальный `data/last_session.json` и восстанавливаются при следующем запуске. Пресеты лежат в `restaurant_presets.json`. Ни один MP3 при этой операции не изменяется.

## Правила формирования и быстрые действия

Вверху — фильтр ресторана и автодобор языков. Настройки по умолчанию в `config.json`: `selection.language_english_percent=50`, `language_tolerance_percent=10`, `prefer_alternation=true`. Допуск и целевой процент можно переопределить в шаблоне ресторана. Когда треков не хватает, процент считается мягким ориентиром. Вручную выбранные песни сохраняются.

Справа одна кнопка **Сохранить M3U8** (также Ctrl+S): сформированные блоки сохраняются с разделителями и резервами, иначе обычный плейлист. Для замены выдели песню справа и новую слева, затем **Заменить ←**. Без выделения слева выбирается следующая альтернатива. Одинаковый тег произведения в плейлист повторно не добавляется.

Рейтинг отображается как число звёзд из 5 с шагом 0,5; оригинальный POPM в MP3 не переписывается. В блоках виден средний рейтинг по оценённым трекам.

Параметры `blocks.vocal_rules` в `config.json` задают мягкие правила: лёгкое начало первого блока, больше лёгких в начале, не более двух средних подряд, лёгкая после сложной, самые сложные ближе к концу выступления. При нехватке песен программа показывает предупреждения вместо искусственного заполнения.

План на следующий этап: баланс рейтингов **между выступлениями** по истории. Пока средний рейтинг только отображается; автоматического равенства рейтингов между выступлениями нет.
