# Синхронизация версий минусов

Согласовывает тег `в-` (кириллическая строчная буква) у разных минусов **одной папки песни**.

## Запуск

1. **Проверить версии.bat** — анализ без изменения MP3, JSON-отчёт в `data/reports`.
2. **Синхронизировать версии — ПРИМЕНИТЬ.bat** — сначала создаёт резервные копии изменяемых MP3, потом меняет только группу `в-` в ID3 `TIT1`. Отчёт также в `data/reports`.

Путь библиотеки, разделитель `_____` и маркер `֎` берутся из главного `../../config.json` (разделы `paths.library_root` и `filename`).

## Правила

- Рассматриваются только непосредственные дочерние папки корня репертуара, а в них — только MP3 с `֎` **на первом уровне**. Вложенные папки не сканируются.
- Если подходящий MP3 только один — никаких действий.
- Если MP3 два или более, проверяются их теги `в-`. Если все совпадают, изменений нет.
- Если хотя бы у одного трека есть `в-`, побеждает **первый в сортировке по имени файл, у которого тег есть**. Этот тег переносится остальным, даже при конфликте.
- Если `в-` нет нигде, тег формируется из названия папки: `Не вспоминай _____ Niletto & Олег Майами & Леша Свик` → `в-Не-вспоминай`. Исполнитель не добавляется; пробелы в названии заменяются дефисами.
- Ручные сокращения сохраняются, если такой тег уже есть у одного из файлов; из названия папки тогда ничего не генерируется.
- Остальные группы `TIT1` и другие ID3-теги сохраняются; аудио не переименовывается.

## Безопасность и повторные запуски

Повторный запуск не переписывает уже согласованные песни. На этапе применения **до записи** для каждой папки создаются полные резервные копии тех MP3, которым требуется обновление. Ошибки попадают в отчёт. Если в одном файле ошибка, папка с проблемой отмечается; другие папки обрабатываются независимо.

Для автоматизации рекомендовано сначала протестировать ручной запуск; планировщик Windows можно подключить позже. Скрипт не устанавливает задачу в планировщик самостоятельно.

CLI: `py -3 sync_versions.py [--apply] [--root ПАПКА] [--report-dir ПАПКА]`.

## Одинаковые названия и каверы

При наличии двух разных оригиналов с одним названием **новые** идентификаторы включают исполнителя после песни: `в-Wonderful-Life-Hurts`, `в-Wonderful-Life-Zucchero`. Уже существующие пользовательские `в-` не переименовываются без явного выбора.

Для папок `(cover)`, `(acoustic)`, `(remix)` и других вариантов формируется `cross_folder_suggestions` в JSON-отчёте; при нескольких возможных оригиналах скрипт печатает отдельный вопрос с вариантами. **Автоматического выбора между оригиналами и записи общих тегов между папками пока нет.** Если папка с кавером содержит несколько MP3 и обнаружена связанная папка, её запись откладывается до ручного решения.
