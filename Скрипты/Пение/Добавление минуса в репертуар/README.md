# Добавление минуса в репертуар

Графическая Windows-программа для одного MP3 за раз.

## Запуск

Запускай:

`Добавить минус в репертуар.pyw`

После обычной синхронизации система ярлыков создаст рядом ярлык на этот PYW. Отдельный BAT не нужен.

На первом запуске, если нет `PySide6` или `mutagen`, программа предложит установить их через pip.

## Основной сценарий

1. Перетащи MP3-минусовку в окно или выбери файл.
2. Программа читает существующие ID3-теги.
3. Заполни/измени теги через понятные списки.
4. При необходимости поправь исполнителя, чистое название, Title, год, источник, тональность и сведения после `֎`.
5. Программа показывает новое имя MP3 и имя папки.
6. Нажми **«Сохранить теги и файл»**.
7. Теги записываются через Mutagen и сразу перечитываются для проверки.
8. После успешной проверки файл переименовывается.
9. Если песня находится внутри:
   `D:\YandexDisk\Проекты\Пение\Минусы\1. Основной репертуар\- - Добавляю в репертуар`
   можно одновременно переименовать и перенести всю папку песни в основной репертуар.

Автоперенос не включается для MP3, открытого из произвольной папки.

## Что редактируется

### Песня и файл
- Исполнитель → TPE1
- Название → MVNM
- Название (Title) → TIT2; по шаблону получает языковой значок `⚪️`, `🔴` или `⚪️🔴`
- Год → TDRC
- Ссылка на плюс → WOAS; это прямой URL на плюсовую/вокальную версию для будущего воспроизведения на сайте
- Альбом автоматически = `минусы`
- тональность — выпадающий список `N, -3, -2, -1, 0, +1, +2, +3`, где `N` = неизвестна
- Примечание — текст после `֎` в имени MP3
- имя MP3 и имя папки генерируются по шаблону, но допускают ручную правку.

### Выступление
- роль в блоке B → TPE2;
- статус G → TXXX:OCCASION;
- сложность SL → TMOO;
- знание текста Z → TIT1;
- характер/энергия K → TCON.

### Поиск и сайт
В TIT1 хранятся:
- аудитория A;
- узнаваемость;
- настроение N;
- язык — **multi-select**, можно одновременно выбрать русский и английский/иностранный;
- эпоха;
- ситуации S.

Языковой значок в Title:
- русский → `⚪️ Название`;
- иностранный → `🔴 Название`;
- русский + иностранный → `⚪️🔴 Название`.

Title можно редактировать вручную; кнопка «По шаблону» возвращает автогенерацию.

### Дополнительно
В TIT1:
- ресторан/площадка R;
- вокальные особенности.

Неизвестные значения TIT1 не удаляются молча: программа сохраняет их и показывает предупреждение.

## Конфигурация

`config.json` — источник вариантов списков, путей и шаблонов.

Изменение вариантов выпадающих списков не требует правки Python.

Текущие пути:
- staging: `D:\YandexDisk\Проекты\Пение\Минусы\1. Основной репертуар\- - Добавляю в репертуар`;
- основной репертуар: `D:\YandexDisk\Проекты\Пение\Минусы\1. Основной репертуар`.

Шаблон папки:
`{clean_title} _____ {artist}`

Шаблон MP3:
`{clean_title} [тональность] _____ {artist} ֎ сведения.mp3`

Если имя MP3 или папки исправлено вручную, автогенерация его больше не перезаписывает до нажатия «По шаблону».

## Безопасность

- существующий файл/папка не перезаписываются;
- запись тегов проверяется повторным чтением;
- при ошибке после записи программа пытается восстановить исходные управляемые теги;
- перенос папки разрешён автоматически только из staging-папки;
- все операции пишутся в локальный `data/operations.jsonl` (он не нужен в GitHub).

## Архитектура

- `Добавить минус в репертуар.pyw` — тихий GUI-запуск без консоли;
- `src/app.py` — PySide6 UI и сценарий обработки;
- `config.json` — поля/варианты/пути;
- `../_common/id3_io.py` — общие операции Mutagen/ID3 для инструментов пения.

Первая версия намеренно не считает ReplayGain, не редактирует lyrics/SYLT, не определяет автоматически сложность/знание текста и не работает пакетно.


## Значения по умолчанию

Для нового/неразмеченного MP3 все смысловые поля стартуют как «Не заполнено» (`#`), кроме:

- **Статус = `г-5-Выучить`**.

Ресторан и вокальные особенности по умолчанию пустые. Никакая аудитория/энергия/роль не подставляется автоматически.

## Справка обозначений

Файл `СПРАВКА.md` содержит таблицу сокращений после `֎`: `мз`, `buy`, `buy-J`, `+click`, `+такт`, `ориг`, `+Б`, `-Б`, `мБ` и др.

В GUI рядом с полем «Примечание» есть кнопка `ⓘ`, которая показывает этот Markdown прямо во встроенном окне. Внешний браузер или отдельный HTML не нужен.


## Версии минуса

В блоке «Песня и название» есть выпадающий редактируемый список **«Версия»**.

Стандартные варианты:
- Обычная — суффикс не добавляется;
- `cover`;
- `remix`;
- `acoustic`;
- `slow ver.`;
- `live`.

Список редактируемый: при необходимости можно ввести своё значение без правки Python.

Версия добавляется **сразу после названия**:
- Title: `⚪️ Название (cover)`;
- MP3: `Название (cover) [-2] _____ Исполнитель ֎ мз.mp3`.

Имя папки версии не содержит и остаётся `Название _____ Исполнитель`, потому что разные версии одной песни должны жить в одной папке.

## Файлы песни

В GUI есть отдельный компактный блок **«Файлы песни»**.

### 📁 Additi0ns

Кнопка создаёт рядом с текущим MP3 подпапку с точным именем:

`Additi0ns`

(ноль вместо буквы O) и сразу открывает её. Папка предназначена для дополнительных версий минуса.

Если папка уже существует, она просто открывается.

### ✂ Копия в Files

Кнопка:
1. создаёт рядом подпапку `Files`;
2. копирует туда текущий MP3;
3. в имени **копии** удаляет только служебный символ `֎`, остальные части имени сохраняет;
4. оригинальный MP3 не меняет;
5. существующий файл не перезаписывает;
6. открывает папку `Files`.

Это заготовка для сценариев, где исходный минус нужно дальше обрезать/редактировать.

## Компоновка экрана

Текущая структура:
1. **Песня и название** — исполнитель, название, версия, Title, итоговое имя MP3 и папки.
2. **Данные минуса** — тональность, год, ссылка на плюс, примечание.
3. **Выступление** + **Поиск и сайт** — две параллельные колонки.
4. **Дополнительно** — ресторан/площадка и вокальные особенности рядом.
5. **Файлы песни** — Additi0ns и Files.
6. **Папка и перенос**.

Если программа продолжит обрастать функциями, следующий UX-шаг — сделать второстепенные блоки («Дополнительно», «Файлы песни», «Папка и перенос») сворачиваемыми, но основной сценарий оставлять всегда видимым.


## F / S — полная и сокращённая версия

В блоке «Данные минуса» рядом с тональностью есть отдельный список:

- `—` — не задано;
- `F — полная`;
- `S — сокращённая`.

Маркер добавляется **после тональности**:

```
Название [-2] [F] _____ Исполнитель ֎ мз.mp3
Название [-2] [S] _____ Исполнитель ֎ мз.mp3
```

И в автоматически формируемый Title:

```
⚪️ Название [-2] [F]
⚪️ Название [-2] [S]
```

При загрузке существующего MP3 программа пытается прочитать F/S сначала из имени файла, затем из существующего Title. Если маркера нет — используется `—`.

Это отдельное свойство от музыкальной версии `cover/remix/acoustic`.

## Загрузка существующих тегов и проверка схемы

При перетаскивании MP3 программа **не переносит значения от предыдущего файла**.

Для каждого нового MP3:
1. читаются его собственные ID3-теги;
2. читаются маркеры версии/тональности/F/S из его имени файла и при необходимости Title;
3. все управляемые списки заполняются значениями именно этого MP3;
4. default используется только если соответствующего значения в MP3 вообще нет.

Текущий default по-прежнему:
- Статус → `Выучить`;
- остальные обязательные смысловые поля → соответствующий `#`;
- ресторан/вокальные особенности → пусто.

### Несовместимые старые значения

Если в управляемом поле MP3 есть значение, которого больше нет в `config.json`, поле подсвечивается красным и показывает старое значение. Например, старое значение сложности/языка/аудитории не будет тихо заменено новым.

Сохранение блокируется, пока красное поле не исправлено.

Если в TIT1 найден структурный тег старой схемы, который уже не относится ни к одной актуальной группе (например, старый префикс), программа показывает отдельное красное предупреждение и также не сохраняет файл до исправления.

Обычные неуправляемые значения без признака старого структурного тега сохраняются и показываются как предупреждение, но не удаляются молча.
