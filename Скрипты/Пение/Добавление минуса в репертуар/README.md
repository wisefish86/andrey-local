# Добавление минуса в репертуар

Графическая Windows-программа для подготовки одной песни: MP3 → теги → имя файла/папки → при необходимости перенос в основной репертуар → загрузка плюса на FTP.

## Запуск

Запускай `Добавить минус в репертуар.pyw` или создаваемый системой ярлык. Отдельный BAT не нужен.

На первом запуске программа предложит установить `PySide6` и `mutagen`, если их нет.

## Интерфейс

Интерфейс организован как сворачиваемые секции:

1. **Песня и файл** — открыта по умолчанию.
2. **Данные песни**.
3. **Теги и подбор**.
4. **Плюс песни**.
5. **Файлы песни**.

Остальные секции можно открывать только когда они нужны, чтобы не прокручивать длинную форму.

### Песня и файл

Здесь находятся поля, влияющие на имя MP3/папки:

- Исполнитель → TPE1.
- Название → MVNM.
- Версия → обычная `—` или `cover/remix/acoustic/slow ver./live`; список редактируемый.
- Название (Title) → TIT2.
- Тональность → `— / N / -3 / -2 / -1 / 0 / +1 / +2 / +3`.
- F/S → `— / F / S`.
- Примечание → часть имени после `֎`.
- Файл минуса — итоговое имя MP3.
- Папка песни — итоговое имя папки.
- Переименовать папку песни по шаблону.
- Перенести папку песни в основной репертуар.

Перенос разрешён **из любого исходного каталога**, а не только из `- - Добавляю в репертуар`. Цель:
`D:\YandexDisk\Проекты\Пение\Минусы\1. Основной репертуар`.

Если папка уже находится непосредственно в основном репертуаре, перенос автоматически не включается.

### Шаблоны имени

Пример:

```
Название (cover) [-2] [S] _____ Исполнитель ֎ мз, +click.mp3
```

Title:

```
⚪️ Название (cover) [-2] [S]
🔴 Title [F]
⚪️🔴 Двуязычная песня [-1] [S]
```

Версия относится к конкретному минусу, поэтому в имя папки она не добавляется:
`Название _____ Исполнитель`.

Title можно редактировать вручную. Кнопка **«По шаблону»** возвращает автогенерацию.

### Тональность

- `—` — маркер в имя не добавляется.
- `N` — тональность неизвестна.
- числа — известная транспозиция.

### Примечание и быстрые чипы

Под полем «Примечание» есть кнопки:

`мз / ориг / инст / оф.инст / buy / buy-J / +click / +такт / +Б / -Б / мБ`.

Нажатие добавляет значение в поле без дублей и автоматически формирует список через запятую. Свободный текст можно дописывать вручную.

Кнопка `ⓘ` открывает встроенный Markdown `СПРАВКА.md`.

## Данные песни

Сейчас здесь хранится год → TDRC. Блок оставлен отдельным для метаданных, которые не формируют имя MP3.

## Теги и подбор

### Выступление
- Роль в блоке B → TPE2.
- Статус G → TXXX:OCCASION.
- Сложность SL → TMOO.
- Знание текста Z → TIT1.
- Характер/энергия K → TCON.

### Поиск и сайт
В TIT1:
- аудитория A;
- узнаваемость;
- настроение;
- язык;
- эпоха;
- ситуации.

Язык — multi-select. Русский + иностранный допустимы одновременно.

### Дополнительно
В TIT1:
- ресторан/площадка;
- вокальные особенности.

## Пустые и обязательные поля

В выпадающих списках пользователь видит просто `—`, хотя внутри ID3 для рабочих групп сохраняется соответствующий тег `#`.

Жёлтым и подчёркнутым подсвечивается **название поля**, если оно действительно требует разметки и пока содержит `#`:

- роль в блоке;
- статус;
- сложность;
- знание текста;
- энергия;
- аудитория;
- узнаваемость;
- язык;
- эпоха;
- ситуации.

Статус по умолчанию = `Выучить`, поэтому он не подсвечивается, пока уже имеет это значение.

Необязательные поля не подсвечиваются: музыкальная версия, тональность, F/S, год, настроение, ресторан, вокальные особенности.

Для ситуаций `с-#` означает «ещё не разобрано». Полностью пустой список после ручной проверки допустим.

Multi-select имеет ту же высоту и центрирование текста, что и обычные dropdown.

## Загрузка существующего MP3

При каждом drag-and-drop программа заново читает только текущий файл.

Порядок:
1. ID3 текущего MP3;
2. версия/тональность/F-S из его имени;
3. при необходимости маркеры из существующего Title;
4. default только если у текущего файла соответствующего значения нет.

Значения предыдущей песни в новый файл не переносятся.

Если существующий управляемый тег отсутствует в текущем `config.json`, поле показывается красным с исходным значением. Сохранение блокируется, пока значение не исправлено.

Старые структурные TIT1-теги с неизвестным префиксом также дают красное предупреждение. Обычные неуправляемые TIT1 не удаляются молча.

## Плюс песни

Отдельная сворачиваемая секция:

1. Перетащи MP3-плюс или выбери файл.
2. Нажми **«Загрузить на FTP»**.
3. После успешной загрузки прямой публичный URL автоматически записывается в поле **«Ссылка на плюс»**.
4. При сохранении минусовки ссылка записывается в WOAS.

Текущая FTP-папка специально вынесена за контур автодеплоя нового сайта, чтобы deploy сайта не удалил загруженные аудиофайлы.

FTP-пароль **никогда не хранится в GitHub/Notion**. При первом использовании программа спрашивает пароль и может сохранить его только локально в `secrets.local.json`; файл есть в `.gitignore`. `secrets.example.json` содержит только пустой шаблон.

При совпадении имени удалённого файла программа спрашивает разрешение на перезапись. После загрузки, если FTP-сервер отдаёт размер, он сверяется с локальным файлом.

## Файлы песни

### 📁 Additi0ns

Создаёт/открывает подпапку `Additi0ns` (цифра 0) рядом с основным минусом для дополнительных версий.

### ✂ Копия в Files

Создаёт `Files`, копирует туда текущий MP3 и у копии удаляет только символ `֎` из имени. Оригинал не изменяется, существующий файл не перезаписывается.

## Сохранение

1. Проверяется схема и конфликты путей.
2. ID3 записываются через общий Mutagen-модуль.
3. MP3 перечитывается и изменённые значения сверяются.
4. Только после успешной проверки переименовывается файл.
5. Затем при выбранных опциях переименовывается/переносится папка.

При ошибке после записи программа пытается восстановить исходные управляемые теги.

Лог локальных операций: `data/operations.jsonl`.

## Конфигурация

`config.json` — источник:
- вариантов списков;
- обязательности подсветки;
- порядка/состояния секций;
- шаблонов имени;
- путей;
- чипов примечания;
- публичных FTP-параметров.

Изменение списков/чипов не требует правки Python.

Общий ID3-модуль:
`../_common/id3_io.py`.

CSV-импортёр и GUI используют одну и ту же реализацию чтения/записи ID3.


## FTP: исправление таймаута 24.10.2026

Исправлена ошибка `cannot read from timed out object`.

Причина: перед загрузкой выполнялся `NLST` для получения списка файлов. Если сервер отдавал таймаут, исключение подавлялось, а программа продолжала работу на уже повреждённом FTP-control connection.

Теперь:
- `NLST` не используется;
- проверка существования выполняется через control-channel команды `MLST/SIZE`;
- после таймаута соединение не переиспользуется;
- загрузка идёт сначала во временный файл `.__uploading__<имя>`;
- размер временного файла сверяется, если сервер поддерживает SIZE;
- только после успешной загрузки временный файл переименовывается в итоговый;
- при ошибке показывается конкретный этап: подключение / вход / каталог / загрузка / проверка;
- таймаут увеличен до 60 секунд;
- используется passive FTP.

Также исправлен целевой каталог. Для аккаунта `andreway` плюс загружается в:
`/www/singer.andreway.ru/audio/plus`

Публичный URL:
`https://singer.andreway.ru/audio/plus/<имя файла>`

Каталог находится внутри `/www/singer.andreway.ru/`, но workflow сайта явно исключает `**/audio/plus/**` из FTP-деплоя.


## Автосохранение и проверка ссылки на плюс

После успешной FTP-загрузки программа делает это **сразу**, независимо от остальных несохранённых полей:

1. Формирует публичный URL вида `https://singer.andreway.ru/audio/plus/<имя>.mp3`.
2. Подставляет URL в поле «Ссылка на плюс».
3. Немедленно записывает URL в `WOAS` текущего MP3-минуса.
4. Перечитывает MP3 через Mutagen и проверяет, что `WOAS` действительно записан.
5. Только затем отдельно проверяет публичную ссылку по HTTP.

Если запись `WOAS` не прошла, программа пытается вернуть старое значение и показывает ошибку. Остальные поля песни при этом не сохраняются автоматически.

### Проверка ссылки

В блоке «Плюс песни» рядом со ссылкой есть две компактные кнопки:

- `✓` — проверить доступность URL;
- `▶` — открыть/проиграть файл по публичной ссылке в системном браузере/проигрывателе.

Статус показывается цветом:
- зелёный — ссылка отвечает HTTP 2xx/3xx;
- красный — 404/другая HTTP-ошибка/сетевая ошибка/таймаут;
- серый — ещё не проверено;
- жёлтый — проверка выполняется.

При загрузке существующего MP3, если в `WOAS` уже есть ссылка, программа автоматически запускает тихую проверку без всплывающего окна. Поэтому потерянный или переехавший плюс будет сразу виден как красная ошибка.

Таймаут HTTP-проверки задаётся в `config.json`:
`plus_upload.http_check_timeout_seconds`.


## Анализ аудио: BPM и ReplayGain через foobar2000

Добавлена отдельная сворачиваемая секция **«Анализ аудио»**.

Путь к foobar2000 хранится в `config.json`:

```
C:\Program Files\foobar2000\foobar2000.exe
```

Кнопка **«♫ Открыть минус в foobar2000»** запускает foobar2000 и передаёт ему путь именно текущего MP3-минуса.

Запуск сделан по полному пути к EXE, а не по имени процесса. Имя процесса подходит для поиска/остановки уже запущенного приложения, но для надёжного запуска используется конкретный executable.

### Рабочий сценарий

1. Перетащить минус в программу.
2. Открыть секцию «Анализ аудио».
3. Нажать **«♫ Открыть минус в foobar2000»**.
4. В foobar2000 выполнить анализ BPM и ReplayGain через установленные контекстные команды.
5. Вернуться в программу.

При возврате программа автоматически перечитывает **только** BPM/ReplayGain из MP3, не перезагружая остальные поля формы и не стирая несохранённые правки.

Также есть ручная кнопка **«↻ Проверить BPM / ReplayGain»**.

### Что проверяется

- BPM → ID3 `TBPM`.
- ReplayGain track gain → `TXXX:replaygain_track_gain`.
- ReplayGain track peak → `TXXX:replaygain_track_peak`.

Статусы:
- зелёный — значение найдено;
- жёлтый — ещё не рассчитано;
- жёлтый с предупреждением — ReplayGain заполнен частично;
- красный — ошибка чтения.

Пример:
- `✓ 93 BPM`;
- `✓ gain -3.63 dB · peak 0.902946`.

Программа сама ReplayGain/BPM пока не вычисляет — foobar2000 остаётся анализатором, а GUI включает этот шаг в единый рабочий цикл и контролирует наличие тегов.

## Парсинг исходного имени, версия, тональность и FTP-slug — 24.10.2026

### Исходное имя MP3

При загрузке программа теперь предпочитает извлекать **Исполнителя** и **Название** из имени самого файла, а не из старых TPE1/MVNM, если имя удаётся разобрать.

Поддерживаются:
- текущий формат `Название _____ Исполнитель ...`;
- обычный формат `Исполнитель - Название`;
- разделители ` - `, ` – `, ` — `.

Пример:

`Ляпис Трубецкой - Я верю [мастер запись].mp3`

разбирается как:
- Исполнитель: `Ляпис Трубецкой`;
- Название: `Я верю`;
- Примечание: `мз`.

Алиасы хвостов в квадратных скобках задаются в `config.json → filename.source_parse.note_aliases`.

### Title

При загрузке нового MP3 существующий TIT2 больше не оставляется как ручной Title. Поле **Title сразу пересобирается по текущему шаблону** после чтения языка/версии/тональности/F-S. Кнопка «По шаблону» остаётся только для возврата после ручной правки.

### Версия

При выборе `cover/remix/acoustic/...` версия добавляется в круглых скобках непосредственно в поле **Название** (MVNM), например:

`Я верю (cover)`

И Title:

`⚪️ Я верю (cover) [-2] [S]`

При смене версии старая известная/пользовательская версия в конце названия заменяется, а не дублируется.

Имя папки остаётся без версии: `Я верю _____ Ляпис Трубецкой`.

### Тональность

`0` удалён из вариантов. Актуальный список:

`— / -3 / -2 / -1 / N / +1 / +2 / +3`

- `—` — ничего не добавлять;
- `N` — тональность неизвестна.

Legacy `[0]` при разборе старого имени трактуется как отсутствие маркера и удаляется из нового имени.

### Внешние программы в JSON

Пути к внешним программам централизованы в:

`config.json → programs`

Сейчас:
- `programs.foobar2000.path = C:\Program Files\foobar2000\foobar2000.exe`;
- `programs.audio_editor.path` — пустая заготовка под Audition или любой другой редактор.

`audio_analysis.program_id` определяет, какой внешний анализатор использовать. Для замены программы достаточно поменять JSON.

### Красивые FTP-ссылки

Локальное имя плюса не меняется. Для сервера создаётся slug.

Пример:

`Капли Абсента (Плюс).mp3`

→

`kapli-absenta-plyus.mp3`

Правила:
- кириллица → латиница;
- нижний регистр;
- пробелы, подчёркивания и пунктуация → дефисы;
- повторные дефисы схлопываются;
- расширение приводится к нижнему регистру.

Параметры и таблица транслитерации находятся в `config.json → plus_upload.slug`.


## Полноширинные секции, статусы и текст песни — 24.10.2026

Все сворачиваемые секции растянуты на всю ширину окна: заголовок целиком работает как большая зона клика.

Актуальный порядок:
1. Песня и файл.
2. Теги и подбор.
3. Текст песни.
4. Анализ аудио.
5. Плюс песни.
6. Файлы песни.

### Статус прямо в заголовке

Для блоков, где есть однозначная автоматическая проверка:
- `✓ Анализ аудио` — есть BPM, ReplayGain track gain и ReplayGain track peak;
- `✕ Анализ аудио` — ошибка чтения;
- `✓ Плюс песни` — публичный URL прошёл HTTP-проверку;
- `✕ Плюс песни` — ссылка не работает/таймаут/HTTP-ошибка;
- `✓ Текст песни` — текст присутствует.

Для «Теги и подбор» отдельную галочку не использовать: там жёлтым/подчёркнутым уже показываются конкретные обязательные незаполненные поля.

### Текст песни

Отдельная сворачиваемая секция содержит:
- большой текстовый редактор;
- «Вставить из буфера»;
- «Очистить»;
- счётчик строк и символов.

Текст сохраняется как обычный несинхронизированный ID3 `USLT`.

`SYLT` программа не изменяет.

Если старый файл содержит единственный USLT с другим языковым кодом, при сохранении он заменяется основным USLT, а не дублируется.

### Язык

Язык теперь **single-select**, а не multi-select:
- —;
- Русский;
- Английский;
- Иностранный.

Для смешанной песни выбирается основной язык исполнителя/исполнения.

Если старый MP3 содержит несколько языковых тегов одновременно, программа показывает поле как несовместимое со схемой и требует выбрать один актуальный язык.


## Ножницы, фиксированный альбом, очистка ID3 и удаление плюса — 24.10.2026

### ✂️ Укоротить

В секции «Песня и файл», рядом с тональностью и F/S, добавлен чекбокс **«✂️ Укоротить»**.

Если включён, Title строится с префиксом:

`✂️ ⚪️ WAKE UP!`

Ножницы влияют только на Title и не добавляются в чистое название, имя файла или папки.

Если существующий TIT2 уже начинается с `✂️`, чекбокс автоматически включается при загрузке MP3.

Символ/подпись/default хранятся в:
`config.json → title.flags.trim`.

### Альбом

В «Теги и подбор → Поиск и сайт» показывается read-only поле:

`Альбом = минусы`

Оно серое и не редактируется из GUI. Значение берётся из:
`config.json → fixed_tags.TALB`.

При сохранении TALB принудительно приводится к этому значению.

### Очистка лишних ID3

После заполнения управляемых тегов программа удаляет все ID3-кадры, которые не входят в явный allowlist:

- TPE1 — Artist;
- TIT2 — Title;
- MVNM — Название;
- TALB — Album;
- TDRC — Year;
- TCON — Genre / энергия;
- TPE2 — роль в блоке;
- TMOO — сложность;
- TIT1 — групповые теги;
- WOAS — ссылка на плюс;
- TBPM — BPM;
- USLT — текст песни;
- SYLT — сохраняется, если присутствует;
- TXXX:OCCASION;
- TXXX:replaygain_track_gain;
- TXXX:replaygain_track_peak.

Например COMMENT, COMPOSER, COPYRIGHT, ENCODEDBY, ORIGARTIST, обычный WWW, APIC и прочие неуправляемые кадры удаляются.

Правила находятся в:
`config.json → id3_cleanup`.

Неуправляемые значения внутри TIT1 больше не сохраняются: при загрузке показывается предупреждение, а при сохранении они удаляются.

Очистка встроена в безопасный цикл сохранения: перед изменением создаётся полный снимок исходных ID3. Если запись или проверка завершается ошибкой, восстанавливается весь исходный набор тегов, включая удалённые кадры.

### Удаление плюса с FTP

В секции «Плюс песни» добавлена кнопка **«🗑 Удалить с FTP»**.

Удаление разрешено только если WOAS указывает на настроенный каталог:
`https://singer.andreway.ru/audio/plus/`.

Перед удалением есть отдельное подтверждение.

После успешного FTP DELETE:
1. файл удаляется с сервера;
2. WOAS текущего MP3 сразу очищается и проверяется;
3. поле ссылки очищается;
4. статус секции «Плюс песни» сбрасывается.

Чужой домен, другой каталог или URL с вложенным путём программа удалять не будет.

Разрешение функции:
`config.json → plus_upload.allow_delete`.


## Тематические песни в «Ситуации / тематика»

Для редких тематических песен не вводится отдельное поле «Универсальность».

Логика:
- `Аудитория / формат → Универсальная` отвечает за широкую применимость по аудитории;
- `Ситуации / тематика` отвечает за конкретную тематическую привязку;
- если песня проверена и специальных ситуаций нет, поле «Ситуации / тематика» можно оставить пустым — это означает отсутствие тематической привязки;
- `с-#` означает только «ещё не разобрано».

Добавлены:
- `с-Детям` — Детям;
- `с-9Мая` — 9 мая;
- `с-23Фев` — 23 февраля;
- `с-Патриот` — Патриотическая;
- `с-Родителям` — Родителям.

`с-НГ` уже существовал и остаётся для новогодних песен.

Поле остаётся multi-select: например, песня может одновременно иметь `с-НГ` и `с-Детям`, либо `с-9Мая` и `с-Патриот`.


## Аудитория для тематических песен

Для тематического репертуара не использовать `а-Унив`.

Существующее значение `а-Ситуац` переименовано в интерфейсе из «Ситуационная» в **«Тематическая»**. Само хранимое значение оставлено без изменения, чтобы не создавать дубликат категории и не требовать миграции старых файлов.

Примеры:
- 9 мая → Аудитория / формат = Тематическая + Ситуации / тематика = 9 мая, Патриотическая;
- 23 февраля → Тематическая + 23 февраля;
- Детям → Тематическая + Детям;
- Родителям → Тематическая + Родителям;
- Новый год может быть как Тематическая, так и Универсальная — по фактическому применению песни.


## Пакетная миграция существующих плюсов на FTP и WOAS

Для уже существующего репертуара добавлен отдельный одноразовый скрипт:

`Инструменты репертуара/Плюсы FTP/Миграция плюсов на FTP.py`

Правило пары:
- **минусовка** — MP3, в имени которого есть символ `֎`;
- **плюс** — MP3 без `֎`, лежащий **непосредственно рядом** с минусовкой в той же папке;
- один плюс может обслуживать несколько минусовок одной песни/версии;
- во вложенные служебные папки скрипт не заходит.

Исключаемые каталоги задаются в:
`config.json → migration_plus_links.exclude_dirs`

Сейчас:
- `Files`;
- `Additi0ns`;
- `Additions`;
- `Editions`;
- `- - Добавляю в репертуар`.

### Безопасность выбора

Автоматически обрабатывается только папка, где:
- есть хотя бы одна MP3-минусовка с `֎`;
- рядом **ровно один** MP3 без `֎`.

Если плюса нет — статус `no_plus`.

Если MP3 без `֎` несколько — `ambiguous_plus`; скрипт ничего не выбирает и ничего не меняет.

Также до применения проверяются коллизии slug: если разные локальные плюсы дают одинаковое FTP-имя, обе папки блокируются как `slug_collision`.

### Dry-run

Запуск:
`Инструменты репертуара/Плюсы FTP/Миграция плюсов - ПРОВЕРКА.bat`

Он:
1. сканирует текущий `paths.library_root`;
2. строит пары «плюс → все минусовки `֎` в этой папке»;
3. читает текущий WOAS;
4. вычисляет FTP-slug и будущий публичный URL;
5. **ничего не загружает и не изменяет**;
6. создаёт JSON + CSV в:
   `data/migration_plus_links`.

### Применение

Запуск:
`Инструменты репертуара/Плюсы FTP/Миграция плюсов - ПРИМЕНИТЬ.bat`

Перед реальными действиями требуется вручную ввести:
`APPLY`.

Для каждой однозначной папки:
1. плюс получает FTP-slug по тем же правилам `plus_upload.slug`, что основная GUI-программа;
2. файл загружается во временное имя;
3. проверяется размер;
4. временный файл переименовывается в итоговый;
5. публичный URL проверяется по HTTP;
6. **только после успешной HTTP-проверки** URL записывается в WOAS всех минусовок `֎` этой папки;
7. WOAS перечитывается и проверяется.

Скрипт меняет у минусовок **только WOAS**. Остальные ID3-теги, имена и файлы не нормализуются и не очищаются этой миграцией.

Если запись WOAS конкретного MP3 падает, его исходные ID3 восстанавливаются из снимка.

### Повторный запуск

Миграция идемпотентна:
- если удалённый файл уже есть и его размер совпадает — он повторно не загружается;
- если WOAS уже равен ожидаемому URL — тег не переписывается;
- если на FTP есть одноимённый файл другого размера — по умолчанию папка останавливается с конфликтом.

Принудительная замена возможна только параметром:
`--overwrite-remote`.

### Фильтры

По умолчанию:
`--filter all`

Можно отдельно запускать:
- `--filter cyrillic` — плюс содержит кириллицу;
- `--filter latin` — плюс без кириллицы.

Транслитерация уже работает для обоих режимов, поэтому технической необходимости в двух проходах нет.

Для проверки одной песни:
`py -3 "Миграция плюсов на FTP.py" --folder "часть названия папки"`

### Новый источник данных для сайта

Актуальный скрипт:

`Инструменты репертуара/Сайт Singer Andrey/Пересканировать репертуар для Singer Andrey.py`

Запуск:

`Инструменты репертуара/Сайт Singer Andrey/Пересканировать репертуар для Singer Andrey.bat`

Сканер:
- рекурсивно читает основной репертуар из `paths.library_root`;

JSON специально не привязан к текущей или будущей верстке Singer Andrey. Сначала существует стабильный слой данных, потом сайт использует его как источник.

Пути к этим инструментам лежат в `config.json → tools`, поэтому их можно переносить/заменять без правки Python GUI.

Это позволяет после добавления или изменения песни сразу из того же окна пересобрать источник данных для сайта.

## Исправление действий папки и расширение лирики — 24.10.2026

### Галочки папки теперь независимы

Состояние чекбоксов читается в момент нажатия «Сохранить»:

- обе сняты → папка не меняется;
- только «Переименовать» → папка переименовывается на текущем месте;
- только «Перенести» → папка переносится в основной репертуар с сохранением текущего имени;
- обе включены → папка переносится и получает имя из поля «Папка песни».

В `data/operations.jsonl` в planned-запись добавлены `folder_action`, `rename_folder_checked`, `move_folder_checked` для проверки фактического сценария.

### Защита staging

Если MP3 лежит прямо в `paths.staging_root` (`- - Добавляю в репертуар`), эта служебная папка никогда не переименовывается и не переносится целиком.

- «Переименовать папку» блокируется;
- при снятом «Перенести» MP3 остаётся в staging;
- при включённом «Перенести» создаётся отдельная папка песни в `library_root`, и туда переносится только текущий MP3.

Превью под чекбоксами теперь явно пишет фактическое действие: без изменений / только переименование / только перенос / перенос + переименование / перенос MP3 из staging.

### Лирика

Исправлена вертикальная политика сворачиваемых секций: большие текстовые поля больше не должны схлопываться до одной строки.

USLT:
- редактируемое поле увеличено до нормальной рабочей высоты;
- сохраняется как раньше.

SYLT:
- читается из MP3 при загрузке;
- показывается отдельным read-only полем ниже USLT;
- строки выводятся с таймкодами `[mm:ss.mmm]`;
- если SYLT нет, программа явно пишет «Синхронная лирика отсутствует.»;
- SYLT программа не изменяет и не перезаписывает.
